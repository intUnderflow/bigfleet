# BigFleet website (`bigfleet.lucy.sh`)

Astro Starlight static site. Source for [https://bigfleet.lucy.sh](https://bigfleet.lucy.sh).

## How content works

The canonical content for everything under `bigfleet.lucy.sh/docs/...` lives in `/docs` at the repo root. **Edit the `/docs` Markdown files**, not the copies under `site/src/content/docs/`.

`scripts/sync-docs.mjs` walks `/docs`, transforms each Markdown file into a Starlight page (extracts the H1 as `title:` frontmatter, rewrites internal `.md` links to clean URLs, strips the leading H1), and writes it to `site/src/content/docs/`. The synced files are listed in `.gitignore` — they never enter version control.

The landing page (`site/src/content/docs/index.mdx`) is hand-written and **not** regenerated by the sync script.

## Local development

```sh
cd site
npm install
npm run dev          # syncs docs, then starts the Astro dev server on :4321
```

The `dev` script runs the sync first; subsequent edits to `/docs` require a re-run (or `npm run sync` separately).

## Production build

```sh
npm run build        # syncs docs and builds to ./dist
npm run preview      # serves ./dist locally
```

## Deploying

The site builds to a static `dist/` directory — deploy to any static host. Recommended: GitHub Pages or Cloudflare Pages, with the build command `npm run build` and the publish directory `site/dist`. A GitHub Actions workflow under `.github/workflows/` should be added when we're ready to publish (not yet committed; pending domain DNS pointing).

## Sidebar / navigation

Configured in `site/astro.config.mjs` under `starlight.sidebar`. When you add a new doc under `/docs`, also add a sidebar entry referencing its clean URL (e.g. `/architecture/` for `docs/architecture.md`).

## Why same-repo

Site source lives next to the engineering source so a single PR can ship code, docs, and the site change together. The sync script means the canonical Markdown stays in `/docs` (where engineers expect it) without duplication.
